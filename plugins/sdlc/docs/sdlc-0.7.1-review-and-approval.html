SDLC 0.7.1 · concept guide

Protect good code. Spend effort where risk lives.

The reviewer still finds defects. It no longer has the power to turn an opinion into a rewrite. Humans get the full design and every delivery promise without having to read the machine database.

1trial fix per package by default
4cost and risk paths
1×final local full-suite run
0raw JSON files humans must read
01 · Why it changed

The old process had two opposite risks

Safety risk

A confident reviewer could damage an approved design

A finding looked like a command. A later agent could apply it without checking authority, trade-offs, or the original design.

Cost risk

Every finding could trigger a worktree and full tests

Preferences and tiny local defects paid the same price as security, contract, or data changes.

New rule: a reviewer finding is a question to verify. The original implementation stays until independent evidence proves one complete trial fix is safer and better.
02 · Review flow

Independent checks remain; expensive roles are conditional

Reviewer

Finds possible defects

Checks the exact approved criteria for this package, design, behavior, repository patterns, naming, and skimmability. It does not edit code.

Evidence checker

Decides whether the finding is real

Uses four results: Valid, Not a problem, Partly right, or Ask human. It also assigns the path.

Trial-fix builder

Builds one coherent correction

Runs only for Light or Full. Compatible findings are combined; the approved semantics remain fixed.

Final checker

Compares the whole trial with the original

It selects at most one Safe improvement. If proof is incomplete, the original wins.

03 · Four paths

Cost follows the blast radius

NO CHANGE

Wrong or preference

No code. No branch. No new test run.

LIGHT

Local and behavior-safe

One shared trial branch, targeted tests, independent diff check.

FULL

High impact

Isolated worktree, targeted tests, explicit semantic invariants.

HUMAN

Authority conflict

Preserve the original and ask one focused design question.

High impact means: business behavior, security, public contract, architecture, data, or operations. High confidence never makes that path cheaper.
04 · Cost control

One combined trial and one final full check

QuestionRuleWhy
One trial per comment?No. One trial per package and review round by default.Compatible corrections must be judged together as one real implementation.
When are several trials allowed?Only for competing alternatives that cannot safely coexist, or separate packages.The state records why one combined trial was impossible.
Full test suite during every role?No. Use targeted checks while reviewing and building.Repeated green builds add cost without adding independent meaning.
When does the full suite run?Exactly once locally after the final commit is selected.If the original stays unchanged, exact passing step-06 evidence must be reused.
Does CI run again?Usually yes.CI is an external publication gate, not another local review role.
05 · Human approval

The human sees the design and the promises—not an artifact dump

Read the complete design. The HTML is a faithful view of the Markdown target solution; it never summarizes or hides sections.
Check every promise. Each criterion has exact wording, a short meaning, why it matters, and a reading priority.
Handle only the remaining choices. Open or semantically changed decisions stay prominent.
Challenge scenarios. The human answers which are wrong and what is missing.
Approve exact content. Hashes and fresh-render checks make a later source or HTML edit visible to every downstream step.
06 · State files

JSON is the machine database; HTML is the human surface

FormatStoresWho reads it
.state.jsonStable IDs, allowed states, package-to-criterion links, counts, commits, test evidence, provenance, approval hashes.Agents and validators. Humans are never required to read it.
.spec.mdThe full design, agreement, rationale, and test scenarios in editable prose.Humans and agents.
.view.htmlA deterministic visual projection: full design or short decision route.Primary human reading surface.
Benefit of JSON: a new session can resume by ID, validators can reject missing or contradictory state, and the HTML page can be regenerated without trusting a chat summary. Before a gate, the validator proves that the HTML exactly matches its source.
Existing 0.7.0 workspaces: a backup-first migration keeps the old JSON beside the new file, reopens the design for the new human summaries, and resumes review before new trial proof. Nothing old is silently treated as proof under the new rules.
