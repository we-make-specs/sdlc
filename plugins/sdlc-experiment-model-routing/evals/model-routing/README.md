# Runtime checks

Use a disposable repository with a declared context registry and a small feature.
Run in the target client with only this delivery plugin enabled. These are manual
acceptance scenarios; packaging checks and the copied validator suite do not
prove runtime model selection or performance.

| Scenario | Expected evidence |
|---|---|
| Fresh kickoff | Available exact model IDs and supported effort shown; one profile question before step work |
| Explicit kickoff choices | User choices win; no duplicate question for supplied values |
| Resume | Saved routing reused; availability rechecked; no re-selection without a changed capability |
| Direct step invocation | Shared policy loaded; missing profile returns to caller before step execution |
| Coordinator model differs | Actual session model is shown; user keeps it or switches through the runtime |
| Stable plugin installed but disabled | Experiment starts; only a competing enabled delivery plugin blocks it |
| Broad research | Two disjoint read-only Scouts overlap, finish, and close before Expert synthesis |
| Scout tool restrictions unavailable | `read-only by instruction` is visible; no claim of enforced permissions |
| Small research or one available slot | Direct narrow inspection or sequential Scouts; reason is visible |
| Scout uncertainty | Exact evidence returned; Expert checks source; no unsupported conclusion |
| Missing optional script | Builder does the same bounded task and acceptance checks |
| Missing required validator or permission denial | Blocked; no Builder substitute and no bypass |
| Model override unsupported or ignored | Explicit capability error or recorded mismatch; no claim of verified routing |
| Runtime does not report actual model or usage | `unreported`, never a worker's self-assertion or invented metric |
| Review with a trial | Reviewer, checker, Builder and final checker stay independent and ordered |
| Human gate | Waits for the actual human; cheaper roles never approve |

For each worker, inspect the invocation's model and effort controls, runtime
metadata when exposed, routing announcement and manifest log. Verify Scout tool
restrictions where supported; otherwise check the disclosed instruction-only
mode and confirm no writes occurred. Scouts never write the manifest. Keep the comparison
to the stable plugin on the same task and source revision, including all worker
usage and retries. Do not publish a speed or savings claim without these results.
